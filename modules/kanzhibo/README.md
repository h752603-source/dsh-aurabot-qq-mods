# 看直播 · kanzhibo

给 [Aurabot（大肥鱼 QQ 插件）](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq) 用的扩展模块。
让大肥鱼在抖音直播间「挂着」，顺便把该做的事做掉。

- 扩展接口：v1（`api: 1`）
- 插件版本要求：>= 1.2.0
- 运行平台：Windows / macOS（要装有 Edge 或 Chrome；Node 需要全局 `WebSocket`，即 22+）

## 它干什么

1. **进直播间**：开一台**独立**的浏览器（自己的 profile，不动你平时用的那个），通过 CDP 挂进直播间。
   给直播间地址最稳（`live.douyin.com/<房间号>` 和 `www.douyin.com/follow/live/<房间号>` 两种都认）；
   给主播主页（`douyin.com/user/...`）会自己找「直播中」点进去。
   已经在同一个直播间里就**不刷新**（刷新会把播放和评论都打断）。
   浏览器**一直以最大化启动**（见下面「窗口为什么必须最大化」）。
2. **进房评论**：等页面真的渲染出评论框（有可见的 `textarea` / `contenteditable`）再发一条你定的评论，一天一次。
3. **续粉丝团灯牌**：先看左上角「今日任务 X/3」——X≥1 就说明今天送过了，直接跳过。
   没送才点粉丝团入口，等面板里出现「1钻 / 可得100亲密度」（或「点亮粉丝团恢复勋章」），
   再按优先级找「送灯牌 / 赠送 / 点亮」按钮。**点完只认面板里出现 `+100`**，
   读不到就退而看聊天区有没有「<昵称>：送出了 粉丝团灯牌」，再退而看进度有没有涨。
4. **送礼物 / 替你说话**（只在主人明说时才做）：开礼物面板 → 按名字找礼物 → 点赠送 →
   用「抖币余额变少 / 出现赠送成功提示 / 飘屏里有礼物名」三个里任意一个确认真的送出去了；
   页面弹充值或抖币不足就立刻停。
5. **私信发弹幕**（0.9.9）：主人在 QQ 私聊里发 `/看直播 说 要说的话`，
   她就在当前挂着看的直播间把这句**原样**发出去（见下面「用法」里的权限说明）。

**总开关**管全部：关掉之后不进房、不评论、不送灯牌、不送礼，浏览器也一并关掉，
她手上只剩一个「模块关着」的状态查询。只读的状态 / 自检 / 面板 / `/probe` 仍然可用。

## 用法

QQ 里（只有主人能发）：

```
/看直播            状态
/看直播 状态       同状态
/看直播 开         打开挂直播并立刻进一次房
/看直播 关         关掉总开关（停定时器、关浏览器、撤待确认）
/看直播 进         立刻进一次房
/看直播 收工       关掉浏览器，半小时内不自己再进
/看直播 自检       体检单：浏览器、CDP、时段、今日评论/灯牌、打法、视口
/看直播 确认       半自动模式下：同意这一下（只能确认一次，90 秒内有效）
/看直播 取消       撤掉待确认，不动手
/看直播 待确认     现在有没有在等我点头的动作
/看直播 灯牌       手动再试一次灯牌（当天连挂 3 次被降级后用它恢复）
/看直播 说 <内容>  在正在看的直播间发一条弹幕（**只认主人本人的 QQ 私聊**；评论 / 弹幕 / 发 是同义词）
```

她自己在聊天里也能用（模型按需调用）：

| 工具 | 什么时候用 |
|---|---|
| `kanzhibo_enter` | 「去看直播」「去 XX 的直播间」「帮我挂着」 |
| `kanzhibo_status` | 「你在看什么直播」 |
| `kanzhibo_stop` | 「别看了」「关掉」「回来吧」 |
| `kanzhibo_gift` | 只有面板「QQ 私信送礼」打开、且是主人的私聊、他明确说了送什么时才用（灯牌不算礼物） |
| `kanzhibo_say` | 「在直播间说一句 XX」——原话照发，一个字不改 |

进房 / 停止 / 送礼 / 说话这四个是**真动作**（开浏览器、改配置、花抖币、用你的号发言），
只有「这一轮有主人说话」时才会挂给她；群里别人开口时她手上只有一个状态查询，而且那个状态不显示在看谁。

送礼另加一道锁：面板里的「QQ 私信送礼」默认**关着**，关着时连工具都不挂给她；打开后也只认主人的**私聊**，
群里（哪怕主人在）不会送。关着的时候你跟她说「送个小心心」，她会告诉你开关没开，而不是嘴上答应。

私信发弹幕（`/看直播 说 <内容>`）的锁：弹幕是用主人的抖音号**公开发出去**的，所以跟送礼同级收紧——
**只认主人本人的 QQ 私聊**，群里发这条命令会被直接拒绝（内容就是主人指定的原话，不像送礼那样花抖币，所以不另设面板开关）。
另有两条护栏：内容最多 50 个字（抖音评论框本身就短）；连发有 10 秒冷却（真发出去了才计时，
连发太快容易触发抖音风控）。命令和她手上的 `kanzhibo_say` 工具共用这个冷却。

## 设置项（`config.json` 的 `ext.kanzhibo`）

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | switch | `false` | **总开关**：关掉后不进房 / 不评论 / 不送灯牌 / 不送礼，浏览器也关掉 |
| `target` | text | `''` | 直播间地址或主播主页 |
| `checkSec` | number | `120` | 多久检查一次（30–1800 秒，改了立刻生效，不用重载） |
| `schedule` | switch | `false` | 只在指定时间段挂 |
| `startTime` / `endTime` | text | `20:00` / `23:30` | 24 小时制，支持跨午夜（`22:30`–`01:00`） |
| `liveCommentOn` | switch | `false` | 启用进房评论（默认关） |
| `liveComment` | textarea | `''` | 评论内容，多行只发第一行 |
| `commentDelaySec` | number | `8` | 进房后等几秒再发 |
| `renewBadge` | switch | `false` | 进房后送灯牌（**有误触风险**：见「续灯牌为什么会点偏」） |
| `badgeDelaySec` | number | `30` | 进房后等几秒才开始送（5–600）。越早越容易点偏 |
| `giftByDm` | switch | `false` | 允许在主人私聊里让她送礼（花抖币；群里永远不送） |
| `semiAuto` | switch | `true` | **半自动**：灯牌 / 送礼真按下去之前截图发私聊，等 `/看直播 确认`。关掉＝自动（照样过命中校验） |
| `confirmSec` | number | `90` | 等你点头多少秒（10–600）；到点没确认就自动撤销，不点 |
| `browserPath` | text | `''` | 浏览器路径；留空 = 自动找 Edge，找不到再找 Chrome。填错会在启动时明确报出来 |
| `minuteReport` | switch | `false` | 进房时在 QQ 里说一声（调试用） |

## 面板怎么排的

七张卡，从上到下（主开关都在卡片标题右侧）：

| # | 卡片 | 内容 |
|---|---|---|
| 1 | **总开关** | `enabled`、直播间或主页、挂的时间段、多久检查一次、浏览器路径、进房时通知我 |
| 2 | **抖音账号** | 「扫码登录」「检查登录」+ 当前登录态（绿=已登录，黄=没登录） |
| 3 | **浏览器窗口** | 「显示浏览器窗口」「收起窗口」 |
| 4 | **运行状态** | 浏览器 / 时段 / 今日评论 / 今日灯牌 / 待确认（有等待时带「确认 / 撤销」按钮）+ 刷新 |
| 5 | **进房评论** | 开关、内容、等几秒 |
| 6 | **粉丝团灯牌** | 开关、等几秒、判定方式说明 |
| 7 | **送礼** | 允许私信送礼、动作前先问我（半自动）、等你多少秒 |

最后有一条通栏警示（灯牌误触 + 抖币花费）。

实现上：模块定义里 `settings` 留空，字段清单放在 `settingsSchema`（自检脚本读它），
面板通过 `draftSettings` / `setSettings` 改草稿，所以底部「保存设置」、未保存提示、离开提醒都照旧。

## 窗口为什么必须最大化

直播间的礼物栏、粉丝团面板、弹幕区都按视口宽度排版：窗口小 → 礼物被收进「更多」（要多点一层）、
面板被浮层挡住。而「候选唯一 + 区域带 + 9 点命中」全建立在「看到完整布局」上。

最大化有四层保障，因为 Chrome / Edge 会**用 profile 里保存的窗口状态覆盖命令行参数**：

1. 启动前改 profile 的 `browser.window_placement`：只置 `maximized: true`，**不写死分辨率**；
2. 命令行走 `--start-maximized`（profile 缺失时兜底）；
3. **`attach()` 里调 `ensureMaximized()`** —— 凡是连上浏览器（新建 / 复用旧窗口 / 模块重载后重连）都执行一次，
   并用 CDP 回读 `windowState` 校验，不是就再请求一次；
4. 每次动手前 `ensureViewport()` 再复核一次。

> 只做第 1、2 层是不够的：关总开关只关窗口、端口还活着，第二次开会走「复用」分支直接跳过启动流程。
## 命令行（不用模型，给人和脚本用）

查状态、跑体检、看候选、走一遍「准备」，以前都得现写一段脚本、读一串 JSON。现在固定成命令：

```bash
cd modules/kanzhibo
node lib/cli.mjs doctor            # 面板连没连上、模块在不在跑、版本对不对
node lib/cli.mjs status            # 挂直播/时段/模式/目标/评论/灯牌/送礼
node lib/cli.mjs pending           # 有没有在等你确认的动作
node lib/cli.mjs confirm | cancel  # 同意 / 撤销那一个
node lib/cli.mjs selfcheck         # 体检单
node lib/cli.mjs probe badge --open --shot        # 探针：打开面板、看候选、截图
node lib/cli.mjs probe gift --name 小心心 --open --shot
node lib/cli.mjs probe text --q 点亮               # 页面里哪些元素含这个词
node lib/cli.mjs verify [--live]   # 跑模块自检（--live 才真起浏览器）
```

- 面板地址：`--base http://127.0.0.1:端口` > 环境变量 `AURABOT_BASE` > 自动扫本机监听端口找 `/aurabot/api/state`。
- 加 `--json` 输出原始 JSON，方便脚本 `jq`；退出码 0 成功 / 1 模块报错 / 2 找不到面板。
- 命令只是把面板里那几个接口固定下来，**不经过模型**，同样的输入给同样的输出，出问题可以原样重放。
## 和「逛电脑」「逛网页」怎么分工

三个模块都在动浏览器/界面，但摊子不一样，别混着用：

| | 看直播（本模块） | 逛电脑 windows-ops | 逛网页 browser-ops |
|---|---|---|---|
| 管什么 | 抖音直播间这一条业务：进房、评论、灯牌、送礼 | 这台电脑的窗口/键鼠/UIA 控件 | 任意网页的通用操作 |
| 怎么定位 | 自己的 finder：文字命中 + 最小可点祖先 + 候选唯一 + 区域带 + 9 点命中；穿透同源 iframe 与影子树 | 优先 UIA 无障碍树（`AutomationId`/`Name`/`ControlType` 选择器），读不到才退回坐标 | CDP：CSS 选择器 + `snapshot` 的 dom/a11y 文本摘要，必要时坐标 |
| 谁做决定 | 模块自己：2 分钟一轮的循环在进程里，关键动作才问人 | 模型：每次操作都是一次工具调用 | 模型：每次操作都是一次工具调用 |
| 花钱/有副作用的动作 | 半自动闸门：截图发私聊，`/看直播 确认` 才点；送礼只认主人私聊 | 风险分级 + `/wops confirm` 批准，键鼠默认关 | 站点白名单 + 面板确认 |
| 典型失败 | 抖音版式变了找不到按钮 → 放弃并报原因 | 界面没有 UIA 树、窗口挪动后坐标偏 | 选择器变、需要登录态 |
| 能不能给别人用 | 目前只给自己用（没导出能力） | 是通用能力层 | 是通用能力层（`api.use('browser-ops')`） |

**优缺点**

- 看直播：**省 token**（循环不经过模型）、**定位最严**（不唯一/被挡就不点），但**只管抖音直播**，抖音改版要跟着修；也没把能力抽出来给别的模块复用。
- 逛电脑：什么界面都能碰（Canvas、游戏、系统弹窗），UIA 树在时很稳；但 Chromium 页面里 UIA 树很浅，用它点网页按钮反而是退步。
- 逛网页：通用、可复用、指引体系完整；但它不知道「这是灯牌」「送出去要花钱」，也没有候选唯一和 9 点命中这套，直播间的关键动作交给它会更容易点偏。

一句话：**窗口用逛电脑，网页用逛网页，直播间用看直播**。真要合并，应该把「find + 命中校验 + 待确认」抽成公共库，让逛网页也能用；那是另一件事，不在这个模块里做。
## 怎么做到「不点错」

四层，缺一层都不行：

1. **窗口最大化 + 坐标系钉死**：启动参数（`--start-maximized`）+ profile 里的 `maximized: true` +
   `attach()` 里再确保一次 + 每次动手前复核，窗口一定是最大化（实测 2560×1313）。
   窗口越小越容易被折叠（礼物收进「更多」、面板被浮层挡），而下面这些判据都建立在「看到完整布局」上。
   同时页面缩放归 1、`prefers-reduced-motion=reduce`。
2. **找元素 + 四道闸门**：文字命中 → 映射到「最小可点祖先」→ 候选必须**唯一**（两个都像就放弃）→
   矩形要落在区域带里（灯牌：左上；礼物：面板内，并且**排除底部那条常驻礼物栏**——那一条点下去也会直接送）→
   9 点采样命中校验（被弹层或别的元素挡住就一律不点）。查找支持**同源 iframe 和影子树**。
   同名按钮有多个时按**优先级表**逐个试（`送灯牌` → `送1个` → `赠送` → `点亮（N钻）` …），
   不是要求全局面板只有一个按钮。
3. **真按之前先给你看**：`semiAuto` 打开时，把要按的位置框成红框截图发私聊，等你 `/看直播 确认` 才动手；
   `confirmSec`（默认 90 秒）不回自动撤；确认时会重新校验一次（元素签名变了就作废）。
4. **点完要有证据**：灯牌按「面板 `+100` → 聊天区播报 → 进度上涨」三级判据；
   送礼按「余额变少 / 赠送成功提示 / 飘屏有礼物名」。

另外：灯牌连续 3 次没成 → 当天降级成「提醒你自己点」，同一原因一天只提醒一次，不再空转。

排查 / 调试接口（默认只读；`open=1` 才会做不花钱的点击）：

    GET /aurabot/api/ext/kanzhibo/probe?what=info          # 当前页 / 视口 / iframe 概况
    GET /aurabot/api/ext/kanzhibo/probe?what=pagetext      # 跨 frame 抓到的整页文字
    GET /aurabot/api/ext/kanzhibo/probe?what=chat          # 聊天区读到的消息行（排查播报用）
    GET /aurabot/api/ext/kanzhibo/probe?what=text&q=点亮    # 页面里哪些元素含这个词
    GET /aurabot/api/ext/kanzhibo/probe?what=badge&esc=1&open=1&shot=1
    GET /aurabot/api/ext/kanzhibo/probe?what=prep          # 走一遍灯牌的「准备」，不点
    GET /aurabot/api/ext/kanzhibo/probe?what=prepgift&name=小心心   # 走一遍送礼的「准备」，不点
    GET /aurabot/api/ext/kanzhibo/pending                  # 有没有在等你确认的

## 续灯牌为什么会点偏

它是在**真实页面上点真实坐标**（`Input.dispatchMouseEvent`），不是调接口，
所以点哪儿全看当时的 DOM：页面没渲染完、抖音改版、窗口拉得很小、左上角临时盖了个弹层，
都可能点偏到顶栏、礼物栏、甚至别人的头像上。这不是「理论上可能」，是这套做法的固有代价。

现在能兜住的：

- **窗口最大化**（见上）—— 布局完整，元素位置才稳定；
- 只认「文字短（≤14 字）、靠左上（top < 90% / left < 80%）、面积够小」的元素，先排掉把整页文字都包进去的大容器；
- 候选必须**唯一**，两个都像就不点；
- 二次确认也只在左上那块面板里找「赠送 / 点亮 / 续费」，不碰底部礼物栏；
- 进房先等 `badgeDelaySec`（默认 30 秒）再动，越早越容易点偏；
- 按下去之前做 **9 点命中采样**：被弹层挡住就不点；
- 点完按三级判据查证据（`+100` → 聊天区播报 → 进度上涨），没证据就不记成功，**当天也不再重试**（避免重复花钱）。

看到它在直播间里乱点，先把「续粉丝团灯牌」关掉，再去面板「日志」页看它到底点了什么（每次点击都会打一条「点了…」）。
## 自检

```bash
node test/verify.test.mjs            # 180 项：注册、权限、总开关、送礼开关、登录/窗口、计时锚点、时段、去重、崩溃恢复、选点/唯一性/签名、闸门、点击器、灯牌判据、面板渲染、0.9.7 优化回归
node --test test/click.test.mjs     # 9 项执行级测试：假 CDP 真跑 find→唯一→命中→点击 全链 + 闸门状态机
node --test test/install.test.mjs   # 3 项「装一遍」验证（复制到临时目录 → import → setup → panel 解析），CI 也跑这个
set LIVE=1 && node test/verify.test.mjs   # 再加 3 项：真起 Edge / CDP 连上 / 收工能关
```

> verify.test.mjs 大多是「源码字符串 grep」，抓不到运行时回归 —— 执行级的兜底在 click.test.mjs（0.9.7 加），
> 它喂假 `evalJs/send` 把点击全链真正执行一遍，不用开浏览器。

脚本喂的是假 `api`：不发 QQ、不改真配置、数据落在临时目录。Windows 用 `set`，macOS/Linux 用 `LIVE=1 node ...`。

QQ 里 `/看直播 自检` 会给一份体检单；面板里也能调 `GET /aurabot/api/ext/kanzhibo/selfcheck`（JSON）。

## 会访问什么、会留下什么

| 访问目标 | 用途 |
|---|---|
| `live.douyin.com/…`、`www.douyin.com/follow/live/…`、`www.douyin.com/user/…` | 进直播间、在主播主页找「直播中」、发评论、点灯牌 / 礼物 |
| `http://127.0.0.1:9300-9699/…` | 本机 CDP，只用来控制它自己启动的那台浏览器 |

除了上面这两类地址，不发任何其它网络请求；Cookie、聊天内容、账号信息都不会被发到别处。

在本机会做三件事：在 `modules-data/kanzhibo/live-profile/`（`api.dataDir()`）里放一个**独立**的浏览器 profile
（这里会有抖音登录态）、在 `state.json` 里记今天评论 / 灯牌做没做过。**不再改任何别的模块的配置。**

## 第一次用要手动登一次抖音

专用浏览器的 profile 在 `plugins-data/aurabot/modules-data/kanzhibo/live-profile/`，
是空账号。第一次让它进房后，在弹出的那个窗口里扫一下码登录——之后一直有效。
没登录也能看，但发评论、送灯牌、送礼都会失败（页面没有对应控件）。

## 它靠什么判断（改代码前先看这里）

| 判断 | 依据 |
|---|---|
| 在不在直播间 | URL 匹配 `live.douyin.com/<数字>` **或** `www.douyin.com/(…/)live/<数字>`（两种都认；也可以只给房间号） |
| 主播还在播吗 | 页面文字出现「直播已结束 / 主播已下播 / 主播离开了」→ 判下播，撤待确认 + 关浏览器 |
| 页面加载完了 | 有可见的 `textarea` / `contenteditable`，或标题含「直播 / 直播间」 |
| 灯牌「今天送过了」 | 左上角「今日任务 X/3」里 X≥1（旧版还看「已完成 / 已送出 / 已领取 / 已点亮」） |
| 要按的是哪个按钮 | `BADGE_CONFIRM_TEXTS` 优先级表：`送灯牌` → `送1个` → `赠送` → `点亮（N钻）` → `点亮` → `续费` … |
| 灯牌送出去了 | ① 面板出现 `+100` → ② 聊天区播报「<昵称>：送出了 粉丝团灯牌」（比点之前多一条）→ ③ 今日任务进度上涨 |
| 评论发出去了 | 点完发送后回读输入框，还含有前 3 个字就算没成功 |
| 礼物送出去了 | 抖币余额变小 / 「赠送成功」提示 / 飘屏出现「礼物名 x N」 |
| 抖币余额 | 礼物栏那一行**最靠右**的纯数字（不取最大值 —— 页面上还有在线观众数、热度） |
| 聊天区在哪 | `[class*="webcast-chatroom___item"]`，一条弹幕一个元素，`textContent` 就是「昵称：内容」 |
| 要充值了 | 页面出现「充值 / 抖币不足 / 余额不足 / 去充值」 |

点击一律走 `lib/click.mjs` 的 `clickOnce`（找 → 唯一性 → 区域带 → 9 点命中 → 真实鼠标事件）。
**代码里没有 `el.click()`** —— 直播间的面板多半按坐标判定，而且 `.click()` 没有任何校验。
## 已知限制

- 抖音改版会换 DOM：找评论框、找「今日任务」、找粉丝团入口都可能失效，报错会写进面板「日志」页（按模块 id 分类）。
- 一台机器同一时间只挂一个直播间（一个 profile 一个窗口）。
- 送礼、发评论都是**用你自己的账号**在真实直播间里的真实动作，没有撤回；点灯牌还可能点偏（见上面那一节）。
- 不处理验证码：页面弹验证码时它只会失败并把原因说出来。
- 抖音现在有**几套直播间版式**（经典版 / 抖音精选外壳），面板可能在 iframe 或影子树里，礼物也可能是
  「点一下就直接送」。模块按「找不到就放弃、绝不盲点」处理；版式对不上时的表现是**没送成 + 日志说明原因**，
  而不是点错。真要看它卡在哪，用上面的 /probe 接口。
- 半自动默认开：不接受 `confirmSec`（默认 90 秒）内回确认，就会放弃这一轮（这是设计，不是故障）。
- **粉丝团面板是 Lynx 渲染的 iframe**（内容画在 canvas 上，`textContent` 是空的）：
  面板里的「送1个基础灯牌 / +100」读不到 DOM 文字。所以灯牌判据只能退到**聊天区播报**和**今日任务进度**，
  抖音哪天连这两条也不给，就只能靠截图人工确认了。
- 聊天区是**虚拟列表**：只能读到当前在 DOM 里的那十几条。点完 20 秒内如果那条播报被刷走，仍可能判失败
  （失败不会重复花钱，只是要你自己看一眼）。
- 点完之后有 13 处固定等待（1200~3500ms）用来等 DOM 渲染。它们不随机器快慢自适应，慢机器上可能偏短。

### 0.9.9 — 新功能：QQ 私信里命令发弹幕（2026-11-09）

主人之前要让她替自己发弹幕，只能自然语言（「在直播间说一句 XX」→ 模型调 `kanzhibo_say`），
模型不在的时候或者想精确控制的时候就没了。这一版加了**直接命令**：

- `/看直播 说 要说的话`（`评论` / `弹幕` / `发` 是同义词；空格可省 `/看直播 说主播加油`；
  成对引号 `「…」` `“…”` 会剥一层）→ 她在当前挂着看的直播间把这句**原样**发出去。
- **权限跟送礼同级收紧**：弹幕是用主人的抖音号**公开发出去**的，所以只认「主人本人的 QQ 私聊」——
  群里发这条命令会被直接拒绝（框架的命令本来就只认主人，但主人也可能在群里敲，那时 `msg.chatId`
  是 `group:…`，照拒；必须是 `private:<主人QQ>` 才放行）。
- **不另设面板开关**：内容就是主人指定的原话，不像送礼那样花抖币，没有误触损失；
  `kanzhibo_say` 工具本来也没有开关，两条路保持一致。
- **两条护栏**：内容最多 50 个字（抖音评论框本身就短，也能挡住误粘贴一大段）；
  连发 10 秒冷却——**真发出去了才计时**，失败（没进直播间、没点成）不占冷却，
  且和 `kanzhibo_say` 工具**共用**，从哪条路发都算。
- 模型规则里补了一句：主人直接发命令时命令会自己执行并回结果，模型不要再调工具重复发一遍。
- verify 208 → 224 项（新增 7.5 节：用法 / 群拒绝 / 别人私聊拒绝 / 来源缺失拒绝 / 长度 / 同义词 /
  失败不占冷却 / 源码回归共 16 条）。

### 0.9.8 — 真机实测修 BUG：灯牌入口点不成 + 面板读不到（2026-11-10）

这一版是**连着真机（抖音 PC 直播页）逐条验过的**，不是纸面审查。改动分四块。

**一、灯牌入口永远点不成（根因，不是「页面没加载好」）**

主人日志里的「挡在上面的是：DIV、DIV」查清楚了：抖音的主播头像/徽章被包在 `pointer-events:none` 的
`<a><span>` 里，所以 `elementFromPoint` 采样时**跳过目标本身**、返回的是它的**祖先容器**。
老的命中校验只认「命中点落在目标里」→ 9 个点全灭 → 「只有 0/9 点命中」→ 粉丝团入口永远点不成。

- 命中校验现在认「命中点是目标的祖先」（点下去照样落在那个祖先上，事件会冒泡），
  但加了**面积 ≤ 8 倍**的护栏，免得整页遮罩被当成「没挡住」。
- 实测：头像徽章 9/9 点命中从 0 变成 9。

**二、粉丝团面板是 Lynx canvas，DOM 里一个字都读不到**

实测当前抖音 PC 版：粉丝团面板是 `DIV#__living_right_panel_id` → `data-e2e="sslocal://lynxview?…"`
→ 一个 `blob:` iframe，里面只有 32 个节点（html/body/lynx-view/script），**零文本节点**；
`document.body.innerText` 里也读不到「加入粉丝团」「送灯牌」。

- 新增 **AX（无障碍树）通道** `lib/ax.mjs`：按 frame 逐个取 `Accessibility.getFullAXTree`
  （面板的树**不在根 frame 里**，只查根 frame 一条都读不到），再用 `DOM.getBoxModel` 取**页面坐标**。
  实测能读到「粉丝团 / 加入粉丝团 / （1钻石）/ 粉丝团专属权益 / 点亮成员 2843 …」，
  坐标也和截图里的按钮位置对得上（实测「加入粉丝团」= `[1756,1156,87,27]`，命中校验 9/9 通过）。
- 面板文字现在 **DOM + AX 一起读**（`panelText()`）；「+100」的口径统一成一个窗口，
  否则「点之前」和「点之后」不是同一把尺子，会把面板里本来就有的 +100 算成这次的。

**三、入口改成结构化定位（不靠文字）**

现在的入口**没有文字**：是头像上的一个图片徽章，class 是哈希（`.PvcS0FNI`）每版都变。
所以改成：昵称元素用 `data-e2e="live-room-nickname"` 定位（这个属性稳定）→ 找它左边那个小方块
→ **悬停**（资料卡是 hover 才出来的 tooltip）→ 点资料卡里的「粉丝团」→ 面板。
实测整条路走通。面板上如果只有「加入粉丝团（1钻石）」，那是**开通**不是续灯牌 → 直接停手并说清楚。

**四、聊天证据认不出抖音现在的文案**

抖音现在的播报是「**送出了 点亮粉丝团 × 1**」，老代码只认「送出了 粉丝团灯牌」→ 灯牌明明送出去了
却报「没确认到送出」。现在两种文案都认（`BADGE_CHAT_RE`）。

**另外一批修掉的 BUG**

| 毛病 | 后果 |
| --- | --- |
| `readBalance` 兜底正则写成 `/(\\d[\\d,]{0,6})\\s*/` | 普通正则字面量里反斜杠只转义一次 → 这条兜底**永远匹配不到**，余额判据整个是死的 |
| `commitGift` 的余额基准在 `clicker.commit` **之后**才补读 | 钱已经扣了，`after < before` 永远不成立 |
| `tick()` catch 里无条件 `cdp.close()` | 一点小异常就掐断 CDP → 半自动「等你确认」的动作作废，主人回「确认」必然失败 |
| `tick()` 失败分支又跑一遍 `badgeSent()` | 它会**真的去点「今日任务」**开合面板（确认前不该再动页面），还会把结论覆盖成自相矛盾 |
| `ensureInRoom` 只比房间号 | 目标是**主播主页**时 wantId 取不到 → 主人换了主播，模块还挂在老主播的房间里 |
| `/probe` 的 `ask/ok/click` 不受 `?open=1` 约束 | 排查接口能直接点灯牌、点任意坐标 → 可能花钱 |
| `cli.mjs` 的 `verify` 指向改名后的 `verify.test.mjs` | `node lib/cli.mjs verify` 必然报文件不存在 |
| `onDispose` 用 `clearInterval` 清 `setTimeout` 的句柄 | 定时器根本清不掉 → 模块停了它还会醒 |
| `tick()` 里 `error.message` 可能 undefined | 报错文案变成空白 |

新增：`lib/ax.mjs`（AX 通道）、`test/ax.test.mjs`（10 项，假的 CDP 真跑）、`/probe?what=ax`（只读地摊开无障碍树）。
verify.test.mjs 180 → 208 项。

### 0.9.7 — 优化与加固（2026-11-09）

行为级的三个「隐性拒绝干活 / 隐性变慢」：

1. **CDP 断开后每个调用白等 20 秒**：ws 断开后 `send()` 是静默丢弃，挂起请求只能等超时 ——
   连接一断，一轮 tick 里每个 `evalJs` 都要卡 20s。加 `closed` 标志，断开直接拒绝。
2. **`hasRecharge` 认「充值」二字太宽**：礼物面板常驻「充值」入口字样，而 commitGift 的检查都在
   开面板之后跑 —— 会永远误判「要充值」，送礼链路可能整个被堵死。只认「余额不足 / 抖币不足」这类结果性文案。
3. **灯牌失败计数成功不归零**：只在跨天清零，同一天「败×2、成、败」也凑满 3 次触发「今天放弃」。送成即归零。

性能：`pageText` 加 400ms 微缓存（一轮原来全页扫 4~6 次）；`findBadgeConfirm` 改合并正则一次扫描
（原来 9 个文字逐个 `prepare`，最坏 90 次全页扫）；DOM 扫描跳过 `script/style/svg` 等三四成无用节点；
`badgeSent` 读完不再开关面板、`prepareBadge` 面板开着时不再点入口（一轮原来最多点「今日任务」3 次）。

健壮：`BROWSERS` 补 LOCALAPPDATA 用户级 Chrome/Chromium；`attach` 优先挑抖音页（多标签不挂错）；
`killBrowserProcess` 覆盖任意 Chromium 系浏览器；`确认` 命令与 tick 互斥（并发会同时操作一个页面）。

运维：截图目录按 7 天滚动清理；半自动红框改按候选 rect 画（合并扫描后 `mark(0)` 可能框错）；
`escapeRe` 一行化、`clampCheckSec` 收敛 6 处重复；新增执行级测试 `test/click.test.mjs`（9 项，假 CDP）。
verify.test.mjs 162 → 180 项。

### 0.9.6 — 两个致命 BUG + 一批小修（2026-11-09）

1. **`r2` 作用域越界**：`const r2` 声明在内层 `else` 块里，外层 `if (sent)` / `else if (!r2…)` 还要用它 ——
   ReferenceError 把 tick 炸进 catch（顺手 `cdp.close()` 断开连接），半自动等确认的**每一轮**都会炸，
   主人回「确认」时目标必然「不见了」。提到外层作用域修掉。
2. **调用已删除的 `myNickname()`**：0.9.1 清死代码时删了函数、留下了调用。它炸在「真点已经按下去之后、
   `badgeDay` 写盘之前」——下一轮 tick 判不出送过，会**再点一次、重复花钻**。判据本来就不靠昵称，改为空。
3. 小修：`checkSec` 挂着时热改不生效（`syncEnabled` 只在没定时器时才 `armTick`，与「改完立刻生效」矛盾）；
   自检 / 面板「不在时段内仍会进房」文案与实际相反（实际是关浏览器不进房）；
   `verifyGiftSent` 拿礼物名直接拼正则（「玫瑰(新)」会抛错，改用 `escapeRe`）；
   verify.test.mjs 头部过时的 `verify/` 路径；日志标签乱码。回归检查补 5 条。
