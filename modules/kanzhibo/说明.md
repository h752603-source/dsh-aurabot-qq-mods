# 看直播（kanzhibo）

给大肥鱼加的本事：在抖音直播间「挂着」，顺便把该做的事做掉。

## 干什么

1. **进直播间**：用一台独立的浏览器（自己的 profile，不动你平时的浏览器）通过 CDP 挂进直播间，
   **窗口一直最大化**（礼物栏 / 面板要完整显示，判据才准）。
   给直播间地址最稳（`live.douyin.com/<房间号>` 和 `www.douyin.com/follow/live/<房间号>` 都认）；
   给主播主页（`douyin.com/user/...`）会自己找「直播中」点进去。
2. **进房评论**：页面真的渲染出评论框之后再发一条你定的评论，一天一次。
3. **续灯牌**：先看左上角「今日任务 X/3」，X≥1 就跳过（今天送过了）；
   没送才点粉丝团入口，等面板出现「1钻 / 可得100亲密度」，再按优先级找「送灯牌 / 赠送 / 点亮」。
   **点完只认面板里的 +100**，读不到就看聊天区有没有「送出了 粉丝团灯牌」，再退而看进度涨没涨。
4. **在 QQ 里用**：`/看直播 开|关|状态|进|收工|自检|确认|取消|灯牌`，以及她自己的工具
   （`kanzhibo_enter` `kanzhibo_status` `kanzhibo_stop` `kanzhibo_say`；
    `kanzhibo_gift` 要多一道锁：面板里「QQ 私信送礼」打开、而且是在你的私聊里，她手上才有这个工具）。
5. **私信发弹幕**（0.9.9）：`/看直播 说 要说的话`（`评论` / `弹幕` / `发` 是同义词，空格可省，
   成对引号剥一层）→ 她在当前挂着看的直播间把这句**原样**发出去。
   **只认主人本人的 QQ 私聊**——群里发这条命令会被直接拒绝（弹幕是用主人的号公开发出去的，
   权限跟送礼同级收紧；但内容就是主人指定的原话，不花抖币，所以不另设面板开关）。
   两条护栏：内容最多 50 个字；连发 10 秒冷却（真发出去了才计时，和 `kanzhibo_say` 工具共用）。

**不再碰别的模块**：0.6.0 起删掉了「进房自动暂停刷抖音」，两个模块各管各的。

## 自检

QQ 里发 `/看直播 自检`（或面板里调 `/aurabot/api/ext/kanzhibo/selfcheck`）会回一份体检单：
浏览器路径、专用 profile、CDP 端口、**视口（含是否已最大化）**、时段在不在内、今日评论 / 灯牌、打法、待确认、最近一条日志。

## 离线自检脚本

```
node test/verify.test.mjs                              # 只测逻辑：224 项（注册、权限、总开关、送礼、私信弹幕、时段、去重、崩溃恢复、选点/唯一性/签名、闸门、点击器、灯牌判据、面板渲染、0.9.7 优化回归、0.9.8 真机修复回归）
node --test test/click.test.mjs                   # 9 项执行级测试：假 CDP 真跑点击全链 + 闸门（0.9.7 加）
node --test test/ax.test.mjs                     # 10 项 AX 通道测试：假的 CDP 真跑无障碍树 + 命中校验（0.9.8 加）
node --test test/install.test.mjs                 # 3 项「装一遍」验证（CI 也跑这个）
set LIVE=1 && node test/verify.test.mjs                # 再加测真浏览器 + CDP
```

脚本给模块喂一个假的 `api`：不发 QQ、不改真配置、数据落在临时目录。

## 变更（按大版本摘要，详细过程见 README 的「变更」）

- **0.9.9** 新功能：私信发弹幕。`/看直播 说 <内容>`（评论 / 弹幕 / 发 同义，空格可省，引号剥一层）
  → 在当前直播间原样发出。权限跟送礼同级收紧（只认主人本人的 QQ 私聊，群里拒绝）；
  不设面板开关（内容是主人指定的原话，不花抖币）。护栏：50 字上限、10 秒连发冷却
  （真发出去才计时，与 `kanzhibo_say` 工具共用）。verify 208 → 224 项。

- **0.9.8** 真机实测修 BUG。灯牌入口永远点不成 —— 抖音的头像徽章被 `pointer-events:none` 包着，
  命中校验把祖先当成「挡板」，9 点全灭（真机日志原文「挡在上面的是：DIV、DIV」）；现在认祖先命中，
  带面积 ≤8 倍护栏。粉丝团面板是 **Lynx canvas**（面板 iframe 里 32 个节点、零文本节点，innerText 读不到），
  新增 **AX 无障碍树通道** `lib/ax.mjs`：按 frame 逐个取树（面板的树不在根 frame 里）+ `DOM.getBoxModel` 取页面坐标，
  实测能读到「加入粉丝团 / （1钻石）」并定位到 `[1756,1156,87,27]`、命中校验 9/9。面板文字改成 DOM + AX 一起读，
  「+100」前后口径统一成一个窗口。入口改成结构化定位：`data-e2e="live-room-nickname"` → 左边的小方块 → 悬停出资料卡
  → 点卡里的「粉丝团」→ 面板（实测走通）；面板上只有「加入粉丝团（1钻石）」就停手（那是开通不是续灯牌）。
  聊天证据认得抖音现在的文案「送出了 点亮粉丝团」。另外修：余额兜底正则双重转义（永远匹配不到）、
  送礼余额基准点在之后才读、tick 出错就掐断 CDP、tick 失败分支多点一次入口、换主播不换房、
  `/probe` 的 ask/ok/click 不受 `?open=1` 约束、cli verify 路径失效、onDispose 定时器清不掉。新增 `test/ax.test.mjs`。
  verify 180 → 208 项。

- **0.9.7** 优化与加固。三个「隐性」问题：CDP 断开后每个调用白等 20 秒（ws.send 静默丢弃）；
  `hasRecharge` 认「充值」二字太宽（礼物面板常驻充值入口，送礼链路可能被整个堵死）；
  灯牌失败计数成功不归零（同一天非连续失败也凑满 3 次触发放弃）。性能：`pageText` 400ms 微缓存、
  `findBadgeConfirm` 合并扫描（原来最坏 90 次全页扫）、DOM 扫描跳过 script/style/svg、
  一轮不再点「今日任务」入口 3 次。健壮：浏览器路径补 LOCALAPPDATA、`attach` 优先挑抖音页、
  杀进程覆盖任意 Chromium 系、`确认` 与 tick 互斥。运维：截图 7 天滚动清理、红框按候选 rect 画、
  新增执行级测试 click.test.mjs。verify 162 → 180 项。

- **0.9.6** 修两个致命 BUG：`r2` 作用域越界（半自动等确认的每一轮都把 tick 炸掉、顺手断开 CDP，
  主人回「确认」必然失败）和调用已删除的 `myNickname`（炸在真点之后、badgeDay 写盘之前，
  下一轮会重复送）。另外：`checkSec` 热改不生效、自检/面板「不在时段内仍会进房」文案与实际相反、
  礼物名没转义就拼正则、verify.test.mjs 里过时的 verify/ 路径。回归检查补 5 条（共 162 项）。
- **0.9.5** 文档修订：README/说明 与代码对齐（8 处过时），变更记录压缩。
- **0.9.2 ~ 0.9.4** 最大化真正生效。`--window-size` 会覆盖 `--start-maximized`（去掉）；
  profile 里 `window_placement.maximized=false` 又会盖掉命令行（启动前改成 true，不写死分辨率）；
